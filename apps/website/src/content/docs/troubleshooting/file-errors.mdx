<InShort>Find the message's title below. Most file errors go away when you move the show to a folder of your own on this computer, one that OneDrive, iCloud or Dropbox doesn't sync, and open it from there.</InShort>

When OpenMarch can't open or save a show, it says why in a message, and the message's link opens this page at its section.

## Invalid file permissions error

OpenMarch isn't allowed to read or write the file. You might see:

- <Ui k="fileAccessDialogError.forbidden.title" /> or "You do not have permission to open this file" when you open it.
- A spinner that never stops.
- An error such as <Ui k="pages.updateFailed" /> when you change something, or changes that are gone the next time you open the show.

Give your user account permission to read and write the file, or move the file to a folder of your own that isn't synced (see [A show in a synced folder](#a-show-in-a-synced-folder)), and open it from there.

### Windows

1. In File Explorer, right-click the file and select **Properties**.
2. Select the **Security** tab.
3. Under **Group or user names**, select your user account.
4. In the permissions list, check that **Read** and **Write** are allowed. If they aren't, or **Deny** is checked, ask whoever manages the computer to give you access.

### macOS

The first time OpenMarch opens a file in your Desktop, Documents or Downloads folder, macOS asks whether to allow it. If you chose not to, allow it in System Settings:

1. Open the Apple menu and select **System Settings**.
2. Select **Privacy & Security**, then **Files & Folders**.
3. Find OpenMarch and turn on the folder your show is in.

If that doesn't help, check the file itself:

1. In Finder, select the file, then choose **File › Get Info**.
2. Open **Sharing & Permissions** at the bottom of the window.
3. Select the lock and enter your password.
4. Set your user name to **Read & Write**.

Apple's [Mac User Guide](https://support.apple.com/guide/mac-help/mchlp1203/mac) explains permissions in more detail.

### Linux

1. Open a terminal in the folder that has the show.
2. Run `ls -l "my show.dots"` to see the file's permissions.
3. Run `chmod u+rw "my show.dots"` to give yourself read and write permission.

## File not found error

<Ui k="fileAccessDialogError.notFound.title" /> means there's no file at the place OpenMarch looked. This usually happens when you open a show from the start page's recent files after the file was moved, renamed or deleted.

1. Find the file where it is now, and open it with <Ui k="launchpage.files.openFile" /> on the start page.
2. On the start page, point at the old entry in <Ui k="launchpage.files.title" /> and select <Ui k="launchpage.files.removeFile" />, or select <Ui k="launchpage.files.clearMissingRecentFiles" /> to remove every entry whose file is gone.

If you didn't open it from the recent files, [report it](/guides/start/get-help/).

## Update OpenMarch to open this file

<Ui k="fileAccessDialogError.tooNew.title" /> means the show was saved by a newer version of OpenMarch than the one you're using. The file hasn't been changed. Update OpenMarch, or [download the latest version](/download/), and open it again.

## A leftover file is stopping this show from opening

<Ui k="fileAccessDialogError.leftoverJournal.title" /> means there's a file next to the show with the same name plus `-journal` (for example `My show.dots-journal`). OpenMarch makes one while it saves and removes it when the save is done. One that's still there is from a save that didn't finish, or it was copied or downloaded along with the show. OpenMarch can't use this one where it is.

Select <Ui k="fileAccessDialogError.leftoverJournal.recover" />. OpenMarch finishes recovering the show on a copy, checks the result, and opens the show. The `-journal` file is moved to OpenMarch's backups folder, not deleted.

- <Ui k="fileDialog.leftoverJournal.damagedTitle" />: the show didn't come out undamaged, with or without the `-journal` file. Nothing was changed. [Report it](/guides/start/get-help/) and include the show and its `-journal` file if you can.
- <Ui k="fileDialog.leftoverJournal.failedTitle" />: OpenMarch couldn't finish. The message says why. Most often the folder isn't writable or the disk is full (see [Invalid file permissions error](#invalid-file-permissions-error)), or another program, such as antivirus or a sync app, has the show open: close it and open the show again.

If the show is in a folder a sync app keeps, the dialog says so. The `-journal` file is likely to come back until you move the show: see [A show in a synced folder](#a-show-in-a-synced-folder).

Older versions of OpenMarch show "Error Loading Database" with "unable to open database file" instead. Don't delete the `-journal` file: if the save it belongs to had started writing, the show needs it. Copy the show and the `-journal` file together into a folder of your own that isn't synced, and open the show from there.

When there's a `-journal` file OpenMarch *can* use, it finishes or undoes the interrupted save by itself, as it always has. Before it does, it puts a copy of the show and the `-journal` file in its backups folder ([Open a show in an older version](/troubleshooting/open-in-an-older-version/) says where that is).

## A show in a synced folder

<Ui k="syncFolderNotice.title" values={{ service: "OneDrive" }} /> appears when a show opens from a folder that a sync app such as OneDrive, iCloud Drive, Dropbox, Google Drive or Box keeps in step with the cloud. While OpenMarch saves, it makes a `-journal` file next to the show and removes it when the save is done. Sync apps can upload, lock or put back that file in the middle of a save, which can leave it behind and stop the show from opening ([A leftover file is stopping this show from opening](#a-leftover-file-is-stopping-this-show-from-opening)). They can also put an older copy of the show back over your changes.

Folders that are often synced without anyone choosing it:

- On Windows, **Documents** and **Desktop** when OneDrive backs them up. The path then has `OneDrive` in it.
- On a Mac, **Documents** and **Desktop** when iCloud's **Desktop & Documents Folders** is turned on.

To move the show:

1. Close OpenMarch.
2. Make a folder that isn't synced. On Windows, for example `C:\OpenMarch`. On a Mac, a folder in your home folder (in Finder, **Go** > **Home**).
3. Move the show into it. If there's a file with the same name plus `-journal` next to the show, move it along with the show.
4. Open the show from the new folder.

To keep a copy in the cloud, copy the show into the synced folder when you're done working, and don't open it from there. Select <Ui k="syncFolderNotice.stopWarning" /> if you want to keep a show where it is anyway.

## Couldn't back up or convert your file

These appear when you open a show from OpenMarch 0.1.7 ([Coming from OpenMarch 0.1](/guides/start/coming-from-0-1/)). In each case your file isn't changed.

- <Ui k="convertShow.openFailed.backupTitle" />: OpenMarch couldn't save the `.pre-conversion.dots` copy, so it didn't convert anything. The message says why. Most often the folder is read-only or you don't have permission to write in it, or the disk is full: move the show to a folder of your own, or free some space, and open it again. If the file is in use by another program, close that program first.
- <Ui k="convertShow.openFailed.convertTitle" />: the conversion failed and was undone. The message names the copy that was saved. [Report it](/guides/start/get-help/) and include the show if you can.

## Server error

<Ui k="fileAccessDialogError.server.title" /> comes from a problem inside OpenMarch, not from your file. [Report it](/guides/start/get-help/), and include the show if you can.

## "Unable to open file" error or render failure

The message says "Unable to open file", or OpenMarch shows <Ui k="fileAccessDialogError.renderFail.title" />. [Report it](/guides/start/get-help/), and include the show if you can.

If a show opens but you get errors while you edit it, see [Repair a show file](/troubleshooting/repair-a-file/).
