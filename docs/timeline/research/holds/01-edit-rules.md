# Edit rules: what each write path does to holds

Every path that writes timeline rows, with what it has to do once hold marks exist (decision 2)
and kept spots are gone (decision 1). The row ids, code locations and current behaviour are in
the appendix inventory, [../keyframe-model/01-write-paths.md](../keyframe-model/01-write-paths.md).
This note adds only the hold rules.

The invariants every path must keep, in the same edit (README, Storage):

- **H-1:** a span lies where the marcher has no move in charge.
- **H-2:** its start is the marcher's arrival (a visible row end, or 0).
- **H-3:** one marcher's spans don't overlap.

The general rules:

- **A new move in charge inside a span** trims the span at the move's start. If the move also
  ends inside the span, the move splits it and the part after the move is dropped. Excursions,
  which would keep that part, are deferred (decision 7).
- **The arrival moves** (its end beat changes): the span's start follows it, and the span's end
  stays where it is. A span left with no length is deleted.
- **The arrival is deleted:** the span is deleted (decision 17).
- **Page-edge edits** (the ripple, flag drags) move span edges that sit on a page boundary, by
  the same rule as row edges (`GridEdgeMap`, `db-functions/timelineRipple.ts:253`).

## Open for ticket D

1. **What Split hold leaves.** Splitting is useful because what follows the split can then be
   edited on its own. If the part after the split is Following, a drag there starts a new set
   (the Following rule) and leaves the first part alone. That may be all a split needs, which
   would make it "end the hold here" and keep H-2 strict.
2. **The upkeep cost.** About 30 paths touch rows, and about half of them can move an arrival or
   start a move inside a span. A shared helper that re-derives spans after each edit could keep
   it down, re-anchoring starts to arrivals and trimming spans where moves are in charge, the way
   the layer module re-derives layers after every edit.
