# Pathways: implementation plan and to-do list

Status: draft 3, 2026-11-06 (model C, lanes on slots: [ADR 0015](../../../adr/0015-lanes-on-slots.md), spec v0.10; new steps 24 to 27, steps 3, 5, 12 and 17 amended, prerequisite B0). Draft 2 was 2026-11-03 (step by step: no up-front schema, turns parked). Model: [draft-model.md](draft-model.md) (draft 5, reference). Controls:
[ux-sheet.md](ux-sheet.md) (draft 3). Decisions: [register](README.md).

## How we build it

The feature ships as **small steps, each one a lab build the owner can try and judge on its own**.
Each step is one PR into an integration branch (`pathways/host`), and does one thing a person can
see. A step lists what to try, what good looks like, and what is deliberately left out, so feedback
is about that step only.

- **One step at a time.** The next step starts once the owner has given the current one a verdict.
- **Feedback changes the plan here.** Each step's row in the tracker records the verdict
  (good / fix / rethink) and any fixes, so nothing gets lost between steps.
- **Lab builds only for steps with something to try.** Steps 1 and 2 are plumbing with a small
  visible piece; the rest each add one behaviour.
- The integration branch goes to main only when everything is in and every check is green.

## Where a path is edited (owner, 2026-11-03)

On the field, with a small floating editor beside the path, as the shape editor works. Not in the
inspector, and not on the Move card. This replaces every Move card control for paths in
[ux-sheet.md](ux-sheet.md) and its earlier drafts (the Drawn / Follow / Turn choice, the point row,
Re-fit, Own routes · Rejoin, and Straight removing a path).

- **On the field:** the pen draws; points drag; right-click or long-press a point for its menu.
- **Opening a path:** with its marcher selected a path is drawn closed, with no handles and no
  editor. A double-click on its line, or **Edit path** in its right-click menu, opens it; Escape, a
  click on empty field or another selection closes it. This moved from step 3 into step 1 (owner,
  2026-11-04: "I don't love how the path is always editable at all times").
- **The floating editor** shows while a path is being drawn or is open, and moves out of the way of
  the handles. Each control is also a named command with its shortcut shown, so the palette,
  keyboard and touch reach the same actions.
- **What it holds grows with the steps:** step 1, who the path is for, Big steps and **Remove
  path**; step 2, Corner / Smooth for the selected point; step 15, Own path · Rejoin; step 3, Re-fit;
  step 5, the selected point's count and Put corners on counts; later, Follow options and turns.
- **Steps per count** applies to straight moves too, so where it lives is settled in its own step
  (#657), not in the path editor by default.
- The Move card's Straight and Arc are refused on a move with a drawn path; Remove path is how a
  path goes (spec AP-R2). What becomes of the Move card is a convergence question, not this one.

## Model C: lanes on slots (ADR 0015)

Owner decision, 2026-11-05 (four open questions settled the same day; accepted 2026-11-06): a group path is **one route, and lanes bind each (transition, slot) to it**. Drawing a path no longer moves marchers out of their move. Overrides are **Adjust** (a tweak owned by the group path, kept through reshapes) and **Detach** (a copy that keeps the group's counts). Spots change hands by count range. Rules: [spec](../../spec.md) v0.10, Appendix J. Reasoning: [model-c/](model-c/README.md).

The model's work is written as changes to the steps above plus four new rows (24 to 27), not as a separate track. Draft 1's M-track maps like this: M0 + M1 → 24; M2 (Detach) and M3 (Adjust) → 3; M4 → 26; M5 → 25; M6 + M7 → 12; M8 → 17; M9 → 27.

### Rules for every step

- **One PR into `pathways/host`, and one lab build** with something to try. This is the plan's
